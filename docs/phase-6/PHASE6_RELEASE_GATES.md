# Phase 6 release gates

These gates are additive and do not change any earlier-phase gate state. Automated evidence can support a gate but cannot close human-review gates.

| Gate | State | Current evidence | Approval still required |
|---|---|---|---|
| `REGION-001` | Open | Region-scoped models, deterministic resolver and synthetic isolation tests | Independent regional-isolation review |
| `SUSSEX-DATA-001` | Open | Empty controlled templates and forced publication block | Authoritative data plus every publication checklist approval |
| `PARTNER-001` | Open | Organisation-scoped roles; no partner-to-case relationship | Independent permission-model review |
| `PROVIDER-001` | Open | State machine and database constraint deny direct provider publication | Workflow/security review |
| `TRANSLATION-001` | Open | Source versioning and high-risk review block | Professional translation, safeguarding and legal process approval |
| `OFFLINE-001` | Open | Public-pack allowlist and private-route cache denial tests | Independent cache/privacy verification |
| `REPORTING-001` | Open | Aggregate-only model and minimum-cell threshold of five | Re-identification risk review |
| `PWA-001` | Open | Installation, push, sync and private caching remain disabled | Shared-device and local-storage privacy approval |
| `ADAPTER-001` | Open | Disabled registry, minimisation and no-submit controls | Adapter security and external owner approval |
| `PHASE6-INTEGRATION-001` | Open | Integration contract and isolated branch | Post-Phase4/5 integration plus independent review |
